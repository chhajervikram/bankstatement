Supported formats & how this works
  • ICICI — Quick Statement: the "OpTransactionHistoryUX3" export. One combined Amount column with a Cr/Dr sign column.
  • ICICI — Detailed Statement: the "OpTransactionHistory" export. Header sits in column B; Withdrawal/Deposit already split; Value Date precedes Transaction Date.
  • Kotak Mahindra: CSV with two "Dr / Cr" columns — only the first (next to Amount) is used.
  • Canara Bank: CSV with no serial number column (generated here), a letterhead preamble, timestamped Txn Date and a "03 Aug 2026"-style Value Date.
  • HDFC Bank: two-digit years, asterisk divider rows, and a trailing "Opening Balance" row that's correctly excluded.
  • Axis Bank: only one date column (used for both Transaction and Value Date); stops at the "Charge breakup" section.
  • PNB: only one date column; Balance carries a trailing "Cr."/"Dr." suffix that's stripped.
  • SBI: only one date column; "Details" cells often contain embedded line breaks that get collapsed into one clean line; Ref No/Cheque No. is usually blank, so the LEFT(4)-of-Description fallback applies here too.
Every parser, and the Excel/CSV file generation, runs entirely in this browser tab — nothing is uploaded anywhere. The "Choose Folder" option (Chrome/Edge only) uses your browser's native File System Access permission so exports save straight into that folder without asking again, until you click "Change Folder" yourself.
